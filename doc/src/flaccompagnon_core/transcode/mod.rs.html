1//! Transcoding detection: was this "lossless" audio once through a lossy
2//! codec?
3//!
4//! # What this looks for
5//!
6//! A lossy encoder scales its transform coefficients, rounds them to integers,
7//! and codes the result. Decoding undoes the scaling but *cannot* undo the
8//! rounding — so the decoded signal's coefficients still sit exactly on the
9//! lattice the encoder put them on. Re-wrapping that signal as FLAC preserves
10//! it bit for bit, lattice included.
11//!
12//! So the test is: reproduce the codec's own analysis chain, scale the
13//! coefficients the way the encoder would have, round them, and measure how
14//! much the rounding actually moved them. On genuine lossless audio the
15//! coefficients fall wherever they like and the error lands near its expected
16//! value for a uniform quantizer. On transcoded audio, at the right alignment
17//! and the right scalefactor, the error collapses towards zero — the values
18//! are *already* on the grid.
19//!
20//! This is statistical evidence, not proof of provenance. The uniform-error
21//! model can fail on tonal or almost-silent bands. Admissibility guards avoid
22//! known false positives, but their sensitivity needs broader validation.
23//!
24//! # Why one detector per codec
25//!
26//! The principle above is codec-independent, but the lattice only exists
27//! *inside the codec's own transform*, and the two transforms have nothing in
28//! common:
29//!
30//! * **AAC** ([`aac`]) takes an MDCT straight off the PCM — 2048-sample long
31//!   windows (1024 coefficients), 256-sample short ones.
32//! * **MP3** takes a hybrid filterbank: a 32-band polyphase filter, *then* an
33//!   18-point MDCT per band, *then* aliasing-reduction butterflies.
34//!
35//! An MP3 lattice viewed through AAC's transform is not a lattice, it is
36//! noise. No amount of threshold tuning bridges that, which is why there are
37//! two detectors and not one with a parameter.
38//!
39//! # Provenance
40//!
41//! The method is Olivier Derrien's, published as:
42//!
43//! * O. Derrien, "Detection of Genuine Lossless Audio Files: Application to
44//!   the MPEG-AAC Codec", *J. Audio Eng. Soc.*, vol. 67, no. 3, pp. 116–123
45//!   (2019 March). [DOI 10.17743/jaes.2019.0002](https://doi.org/10.17743/jaes.2019.0002)
46//!
47//! **This is an independent implementation written from the equations in that
48//! paper**, not a translation of the author's MATLAB reference. That
49//! distinction is deliberate and it matters: the reference distribution is
50//! marked "personal use or research purpose, commercial use prohibited", which
51//! is incompatible with this project's MIT licence. An algorithm published in
52//! a journal may be implemented freely; a particular implementation of it may
53//! not be copied. Every constant below is traceable either to a numbered
54//! equation in the paper or to the MPEG standard it comes from, and says so.
55//!
56//! Where the paper is ambiguous, the choice made here is stated at the point
57//! it is made rather than silently resolved.

71/// One scalefactor band: a half-open range of coefficient indices.
72///
73/// Shared by both codecs. The *values* differ per standard and per sample
74/// rate, but the shape of the idea does not, and the criterion that consumes
75/// them treats a band as a band.
76#[derive(Debug, Clone, Copy, PartialEq, Eq)]
77pub struct Band {
78    /// First coefficient index, inclusive.
79    pub start: usize,
80    /// One past the last coefficient index.
81    pub end: usize,
82}
83
84impl Band {
85    /// Number of coefficients in the band.
86    pub fn width(&self) -> usize {
87        self.end - self.start
88    }
89}

91/// What a codec detector concluded about one file.
92#[derive(Debug, Clone, Copy, PartialEq)]
93pub struct TranscodeEvidence {
94    /// The detection criterion `L` from the paper's §1.4: the fraction of
95    /// (subband, scalefactor) trials whose rounding error fell below its
96    /// threshold. The best shape's counts are pooled across frames, then
97    /// maximized over alignments and selected channel signals. In `0..=1`,
98    /// but NOT a calibrated probability of having a lossy source.
99    pub likelihood: f64,
100    /// The sample alignment that produced [`Self::likelihood`]. Meaningful
101    /// as a diagnostic only: even genuine lossless audio has a winning
102    /// offset, so this value alone does not establish synchronization.
103    pub offset: usize,
104    /// Whether [`Self::likelihood`] cleared the codec's significance
105    /// threshold — the actual verdict.
106    pub detected: bool,
107}

109/// Why the lattice search produced no verdict.
110///
111/// The detectors return `Option`, and for a long time so did the pipeline —
112/// which meant every reason a file went unmeasured collapsed into the same
113/// silent `None`, indistinguishable from each other and, in the table, from a
114/// clean result. A dash in the Lattice column then said "something went
115/// wrong somewhere" and nothing more, which is not enough to act on.
116///
117/// So the reason is carried instead of discarded. It costs one enum and it
118/// turns "the detector didn't run" from a dead end into a diagnosis.
119#[derive(Debug, Clone, PartialEq, Eq)]
120pub enum LatticeSkip {
121    /// The file could not be decoded a second time. Carries the decoder's own
122    /// message, since that is the only thing that says *why*.
123    Undecodable(String),
124    /// Decoding succeeded but produced no usable samples.
125    NoSamples,
126    /// The sample rate has no tabulated scalefactor bands — see
127    /// [`supported_rate_khz`].
128    UnsupportedRate(u32),
129    /// Fewer frames than one sweep needs.
130    TooShort,
131    /// The user cancelled the analysis.
132    Cancelled,
133}
134
135impl std::fmt::Display for LatticeSkip {
136    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
137        match self {
138            Self::Undecodable(e) => write!(f, "the file could not be decoded a second time ({e})"),
139            Self::NoSamples => write!(f, "the decoder returned no samples"),
140            Self::UnsupportedRate(hz) => write!(
141                f,
142                "{:.1} kHz has no tabulated scalefactor bands (only 32, 44.1 and 48 kHz do)",
143                *hz as f64 / 1000.0
144            ),
145            Self::TooShort => write!(f, "the file is too short for all requested analysis windows; transcoding is inconclusive"),
146            Self::Cancelled => write!(f, "the analysis was cancelled"),
147        }
148    }
149}

151/// What the lattice search concluded, or why it could not conclude anything.
152pub type LatticeResult = Result<TranscodeEvidence, LatticeSkip>;
153
154/// Sample rates the detectors handle, in kHz.
155///
156/// The scalefactor band tables are defined per sample rate by the MPEG
157/// standards; only these three are tabulated here. Other rates are outside
158/// this detector's scope, not evidence against a lossy source. Resampling
159/// can follow lossy decoding, so upsampling and transcoding may coexist.
160pub fn supported_rate_khz(sample_rate: u32) -> Option<u32> {
161    match sample_rate {
162        32_000 => Some(32),
163        44_100 => Some(44),
164        48_000 => Some(48),
165        _ => None,
166    }
167}
